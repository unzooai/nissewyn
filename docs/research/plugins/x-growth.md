# Xtools 重新设计：任何人都能用的 X 涨粉运营插件

> 状态：设计稿，待确认。上一版 Xtools 是 Xdoaipm 的改版（写死了 AI 领域、@zhitong45、中美双时区）。
> 这一版从零写，只借鉴它的打法，不用它的代码。

## 1. 从 Xdoaipm 学到的打法（去掉领域之后还成立的部分）

| Xdoaipm 的做法 | 背后的通用道理 | 新设计里怎么体现 |
|---|---|---|
| 中美双时区接力 | 在**受众醒着的时候**出现 | 受众时区由用户填/从粉丝互动时间推断，可多个 |
| 分时段会话：刷流 → 回通知 → 前排回大V → 关键字互动 → 关注 | 像真人一样**一阵一阵地**活跃，而不是匀速刷 | 「会话」保留，内容由打法决定 |
| 大V新帖前排狙击 | 在同领域大号**新帖早期**留下有信息量的回复，借流量 | 「前排回复」：盯用户自己选的同行/大号 |
| 读者通知闭环 | 回应读者是权重最高、最安全的互动 | 「通知收件箱」：第一优先级 |
| 情报雷达长帖 | 基于**最近 24h 本领域的一手讨论**写原创 | 「领域雷达」：领域、信源由用户定 |
| 选题池轮转 + 开发日志 | 稳定的内容支柱 + 真实素材 | 「内容支柱」+「素材源」（笔记、链接、RSS、git） |
| 人设、去 AI 味、红线 | 声音一致、像人、不踩雷 | 「声音」：从用户自己的历史帖学；红线由用户定 |
| 防封：上限、养号、熔断 | 账号是唯一资产 | 保留，默认更保守 |
| 效果快照、关键字效果、日报 | 量化 | 加一步：**用结果反过来调打法**（Xdoaipm 没有） |

## 2. 产品定位

**你的 X 账号运营助理**：告诉它你是谁、想吸引谁，它帮你每天发对的内容、在对的时间出现、
把读者和同行的互动接住，并且每周告诉你什么有效、自动调整下周的打法。

- 任何领域、任何语言、一个账号（个人或品牌）。
- 不带任何预设领域、账号、产品、链接。

## 3. 用户要给的（第一次打开时的引导，5 分钟）

1. **账号**：选登录了 X 的浏览器身份（Unzoo One 的角色绑定）。
2. **你是谁**：一句话定位 + 想吸引的人 + 目标（涨粉 / 给网站或产品引流 / 建立专业影响力）。
3. **它自己去读**：你的主页、最近 100 条帖和它们的数据 → 总结出
   - 你的声音（句式、长度、语言、常用词，给写稿当范例）；
   - 你哪类帖表现好（主题、格式、时间）；
   - 你的读者在什么时区活跃。
4. **它给出打法草案**（可改）：内容支柱 3–5 个、每周节奏、要盯的同行和关键字（从你的领域和互动对象里找）。

之后日常不需要再填表。

## 4. 每天做什么

```
           领域雷达（同行新帖、关键字热帖、素材源）
                       │
     ┌─────────────────┼─────────────────┐
     ▼                 ▼                 ▼
  原创草稿          前排回复草稿        引用草稿
     │                 │                 │
     └──────── 审批队列（一屏批量过，键盘操作）────────┘
                       │
             排程：按受众活跃时段错开发出
                       │
       通知收件箱 ← 读者回复/提及（第一优先级）
                       │
       效果采集 → 周报 → 自动调整下周打法
```

- **原创**：每天 N 条，按支柱轮转；格式：短帖、thread、长文、配图卡。素材来自雷达、你的笔记/链接/RSS/git。
- **前排回复**：盯的账号发新帖后 N 小时内、回复还少时，起草一条有信息量的回复。
- **通知收件箱**：读者的提问优先起草回答；附和类只建议点赞。
- **会话**：在受众活跃时段，把已批准的回复、点赞、关注分散成几阵执行。

## 5. 自动化的边界（默认值）

默认**全自动**（用户的决定）：原创、回读者、前排回复、引用、点赞、关注都按节奏直接执行。

| 动作 | 默认 | 可改成 |
|---|---|---|
| 发自己的原创 | 自动排程发 | 先审批 |
| 回读者通知 | 自动 | 先审批 |
| 前排回复、引用 | 自动 | 先审批 |
| 点赞、关注 | 自动 | 关掉 |
| 读数据、雷达、周报 | 自动 | — |

- 第一次打开时明确告诉用户：X 的自动化规则不允许按关键字/批量自动回复、关注、点赞，
  账号被限流或封禁的风险由用户承担；每一类都能单独改成「先审批」。
- 全自动下审批队列仍然在：可以随时看到将要做什么、撤回或暂停。
- 对话里的智能体调用插件的发送类工具，仍然经过 Unzoo One 的审批（工具标 send）。

## 6. 学习闭环（比 Xdoaipm 多的一步）

每周：哪个支柱、格式、时段、哪类前排回复带来了关注和互动 → 调整下周支柱权重、发帖时段、
盯的账号（加有效的、减无效的）、关键字。改动列在周报里，你可以撤回。

## 7. 安全

- 每天上限、养号期（新号自动减量）、每小时动作上限、动作间隔。
- 每次动作后检查页面：被限流/验证/锁号 → 停下并告诉你，不重试。
- 红线：用户自己填（默认：政治、仇恨、成人、金融承诺建议不碰）；回复前也检查对方原帖。
- 不重复：同一条帖不互动两次；同一个人 24 小时只回一次。

## 8. 在 Unzoo One 里

- 插件清单：角色 `account`（浏览器身份）、`writer`（智能体+模型）、`designer`（可选，出图）。
- 设置页：受众时区、每天原创数、会话时段、各项上限、自动化开关、红线。
- 控制页面：今天 / 审批队列 / 收件箱 / 雷达 / 打法 / 周报。
- 给对话里的智能体的工具：`draft_post`、`queue`（读）、`approve`（send）、`report`（读）……
- 数据存在插件数据目录（SQLite），不上云。

## 9. 代码

从零写（Python 标准库 + Unzoo 浏览器 REST），不复制 Xdoaipm 的代码，所以可以放进 Unzoo One 仓库、对外发布。
X 的页面操作（发帖、thread、回复、引用、点赞、关注、读时间线/通知/主页数据）单独一个模块，
加上页面变化时的自检。

## 10. 分期

1. **能用**：引导 → 读历史帖学声音和打法 → 原创草稿 → 审批 → 排程发；通知收件箱；粉丝快照。
2. **涨粉**：领域雷达（同行、关键字）→ 前排回复/引用草稿；会话执行；发现新同行。
3. **会学**：效果归因、周报、自动调整打法。
